# 兔南掌柜问数 · 项目说明

## 一句话介绍

兔南掌柜问数是一个面向数据仓库场景的智能数据问答系统。用户只需要用中文提问，系统就会自动理解业务意图、召回相关表字段和指标口径、生成只读 SQL、查询数据，并把结果整理成表格、图表和文字洞察。

它解决的问题很直接：**让不会写 SQL 的业务人员，也能快速从数据仓库里拿到可信答案。**

- 公网演示：https://tunan-zhanggui-wenshu.builtbluebell8.chatgpt.site
- GitHub：https://github.com/wine1133/tunan-zhanggui-wenshu
- 技术形态：Next.js / Vinext 全栈应用 + Cloudflare Workers + Cloudflare D1

## 项目背景

传统数据仓库通常存在三个使用门槛：

1. 业务人员需要提交需求，等待数据分析师排期。
2. 临时分析依赖 SQL，非技术用户难以独立完成。
3. 同名指标口径不统一，分析结果容易被误读。

掌柜问数参考 RAG（检索增强生成）思路，把数据仓库的元数据作为知识库：先从问题中识别分析意图，再检索相关表、字段、指标和维度值，最后在受控范围内生成只读 SQL 并执行。这样既提高了查询效率，也保留了分析过程的可追溯性。

## 目标用户

- 业务运营：查询销售、商品、地区和客户表现。
- 门店或区域负责人：查看区域贡献、销量排名和趋势。
- 数据分析师：快速完成重复性取数和初步洞察。
- 数据团队：统一维护指标口径和元数据说明。
- 教学与演示场景：展示 NL2SQL、RAG、数据可视化与全栈部署的完整闭环。

## 核心功能

### 1. 自然语言问数

支持以下常见分析表达：

- 统计华北地区销售总额
- 2025 年各地区销售总额
- 2025 年各个商品的销量
- 各地区销量排名前三的商品
- 按月份看 2025 年销售趋势
- 各会员等级的客单价
- 各品牌销售额排名

系统可以识别年份、地区、商品、品类、品牌、会员等级和性别等筛选条件，并匹配地区、商品、月份、季度、客户等分析维度。

### 2. 元数据召回

元数据知识库包含表说明、字段角色、字段别名、示例值、指标定义和指标关联字段。问数时会召回相关表、字段和指标，让生成 SQL 的依据更清晰。

### 3. 只读 SQL 生成与安全校验

- 用户输入不会被直接拼接成 SQL。
- 服务端通过受控模板生成查询。
- 只允许 `SELECT` / `WITH` 查询。
- 禁止写操作、多语句和注释注入。
- 筛选值使用 D1 Prepared Statement 绑定。
- 前端可以查看最终 SQL，方便复核。

### 4. SSE 流式执行反馈

前端通过 SSE 实时展示执行链路：

```text
理解问题 → 召回元数据 → 生成 SQL → 安全校验 → 执行查询 → 生成洞察
```

即使查询需要等待，用户也能清楚知道系统正在做什么。

### 5. 自动可视化

系统根据问题自动选择适合的展示方式：

- 单指标汇总：指标卡
- 地区、商品、品类、品牌：横向柱状图
- 月份、季度：折线趋势图
- 明细分析：结果表格
- 自动结论：突出最高项、占比、趋势变化和排名信息

### 6. 数据资产视图

- **数据地图**：查看 5 张数仓表的字段、类型、角色和业务描述。
- **指标中心**：查看指标含义、计算口径和业务别名。
- **查询历史**：保存最近的问数记录，并支持重新执行。

### 7. 三屏品牌轮播

首页使用三屏自动轮播，分别介绍：

1. 自然语言问数：从业务问题到可信答案。
2. 可追溯 SQL：召回、校验、执行全过程可见。
3. 自动洞察：趋势、结构和排名一屏读懂。

每屏配有真实商业摄影素材，并叠加当前业务场景的数据摘要。

## 系统工作流程

```text
用户中文问题
    │
    ▼
意图解析：指标 + 维度 + 筛选条件
    │
    ▼
元数据召回：表、字段、指标、别名
    │
    ▼
SQL 生成：受控查询模板 + 参数绑定
    │
    ▼
安全校验：只读语句白名单
    │
    ▼
D1 数据仓库执行
    │
    ├── 结果表格
    ├── 自动图表
    ├── 文字洞察
    └── 查询历史
```

## 数据模型

项目采用订单分析星型模型：

- `fact_order`：订单事实表，包含订单数量和订单金额。
- `dim_date`：日期维度，包含年、季度、月、日。
- `dim_region`：地区维度，包含省份、大区和国家。
- `dim_product`：商品维度，包含商品、品类和品牌。
- `dim_customer`：客户维度，包含姓名、性别和会员等级。
- `table_info`：表描述信息。
- `column_info`：字段描述、角色、别名和示例值。
- `metric_info`：指标名称、口径、别名和依赖字段。
- `column_metric`：字段与指标的关联关系。
- `query_history`：查询问题、SQL、耗时、行数和执行状态。

当前演示数据包含 2024—2025 年共 3,655 条订单，覆盖 5 个地区、10 个商品、16 个客户和多个会员等级。

## API 说明

### `GET /api/overview`

返回首页概览数据：

- 累计销售额、订单数、客户数和平均客单价
- 2025 年月度趋势
- 地区贡献排行
- 品类结构
- 最近查询历史

### `GET /api/catalog`

返回数据地图和指标中心所需元数据：

- 表、字段、角色和描述
- 指标定义和业务别名

### `POST /api/query`

请求体：

```json
{
  "question": "2025年各地区销售总额"
}
```

通过 SSE 返回执行阶段和查询结果。最终结果包含 SQL、数据行、列名、召回信息、图表配置、文字洞察、耗时和行数。

## 安全与可靠性

- 只读 SQL 执行，拒绝写操作。
- 用户输入与 SQL 参数分离。
- 查询问题限制在 300 字以内。
- 服务端对查询问题做空值和长度校验。
- 查询历史仅保留最近 200 条。
- 前端显示执行阶段、召回结果和最终 SQL。
- 首次访问自动幂等写入样例数据。
- 对没有匹配结果的问题给出可操作提示，不返回空白页。

## 项目亮点

1. **完整闭环**：不是只生成 SQL，而是覆盖召回、生成、校验、执行、可视化和历史留存。
2. **过程可追溯**：用户能看到召回的表字段、指标和最终 SQL。
3. **对业务人员友好**：用中文表达问题，不需要学习 SQL。
4. **可视化自动匹配**：根据问题类型选择指标卡、柱状图、折线图或表格。
5. **低运维部署**：前端、API 和数据库统一部署到 Sites + D1，无需单独维护 MySQL、Qdrant 和 Elasticsearch 集群。
6. **品牌化体验**：兔南品牌视觉、三屏轮播、真实商业摄影和统一的数据分析界面。

## 当前版本边界

当前公网版本采用“规则化语义解析 + 元数据召回”的确定性 NL2SQL 内核，不依赖外部大模型密钥，因此演示稳定、响应快、结果可预测。

它适合作为课程项目、产品原型和 NL2SQL 流程演示。对于更复杂的多表自由分析、同义词长尾表达和开放式业务问题，可以进一步接入大模型、向量数据库与全文检索引擎。

## 后续规划

- 支持 MySQL、Hive、ClickHouse 等生产数据源。
- 增加用户登录、租户隔离、权限控制和查询审计。
- 支持图表导出、结果下载和定时报表。
- 增加自然语言追问和多轮上下文记忆。
